# 실시간 음성 인식 및 회의록

노트북의 기본 마이크로 대면 회의를 녹음합니다. 왼쪽에 한국어 자막을, 오른쪽에 핵심 안건, 주요 논의 및 결정 사항, 담당자별 할 일을 표시합니다.

화면과 결과 파일은 노트북에서 열립니다. 음성 인식은 음성 조각과 짧은 이전 자막을, 요약은 인식된 자막과 기존 회의록을 Google Gemini로 전송하므로 인터넷 연결이 필요합니다. 녹음과 외부 서비스 전송을 참가자에게 알리고, 사내 데이터 처리 정책에 맞는 회의에서 사용하세요. 원본 음성 파일은 저장하지 않습니다.

## Ubuntu에 설치하기

1. Intel 또는 AMD 64비트 Ubuntu에서 `dist/meet-docs_1.3.0_amd64.deb`를 설치합니다. 프로젝트 폴더에서 아래 명령을 실행하면 Ubuntu가 필요한 시스템 패키지도 설치합니다. 기존 설치본도 같은 명령으로 업데이트할 수 있습니다.

   ```bash
   sudo apt install ./dist/meet-docs_1.3.0_amd64.deb
   ```

2. Ubuntu **설정 → 소리 → 입력**에서 내장 마이크를 기본 장치로 선택합니다.
3. 앱 목록에서 **실시간 회의록**을 열고 **Gemini API 키**를 입력합니다. 앱에 필요한 Python과 Python 패키지는 설치 파일에 포함되어 있습니다.
4. 파일을 저장할 때까지 앱을 열어 두세요. 결과는 기본적으로 `~/.local/share/meet-docs/output/`에 저장되며 앱의 **저장 폴더 열기**로 확인할 수 있습니다. 저장 위치는 `XDG_DATA_HOME`을 설정했다면 해당 디렉터리 아래의 `meet-docs/output/`입니다.

파일로 키를 설정하려면 위 저장 위치의 `meet-docs` 폴더에 `.env`를 만듭니다. 아래 [연결 키 설정하기](#연결-키-설정하기)의 변수 이름을 그대로 사용하세요.

설치 파일을 다시 빌드하려면 x86-64 Linux에서 `uv`와 `dpkg-deb`를 설치한 뒤 프로젝트 폴더에서 `python3 ubuntu/build_deb.py`를 실행합니다. Ubuntu 패키지에는 `ubuntu/requirements.lock`에 버전과 파일 해시가 기록된 Python 패키지를 사용합니다.

## Windows에 설치하기

1. 프로젝트 압축을 풀고, `run.bat`와 `app.py`가 같은 폴더에 있는지 확인합니다. 쓰기가 가능한 로컬 폴더를 사용하세요.
2. 64비트 Python 3.12 또는 3.11을 설치합니다. **Python 설치 관리자**를 받은 경우 설치 후 명령 프롬프트에서 `py install 3.12`를 실행합니다. 독립 설치 프로그램을 사용하는 경우 첫 화면에서 **Add Python to PATH**를 선택합니다. 그러면 명령 프롬프트가 Python을 찾을 수 있습니다. [Python Windows 다운로드](https://www.python.org/downloads/windows/) · [Windows 설치 공식 문서](https://docs.python.org/3/using/windows.html)
3. Windows 11의 **설정 → 시스템 → 소리 → 입력**에서 ThinkBook 내장 마이크를 기본 입력으로 선택합니다. 입력 장치 이름은 드라이버에 따라 다릅니다. 말을 할 때 입력 막대가 움직이는지 확인합니다. **설정 → 개인정보 및 보안 → 마이크**에서 마이크 액세스, 앱의 마이크 액세스, 데스크톱 앱의 마이크 액세스를 켭니다. 마이크 음소거 키나 헤드셋 연결에 따라 기본 입력이 바뀔 수 있습니다. [Microsoft 마이크 점검 안내](https://support.microsoft.com/en-au/windows/hardware/drivers/fix-microphone-problems)
4. `run.bat`를 더블클릭합니다. 처음 실행하면 `.venv`라는 프로젝트 전용 Python 환경을 만들고 필요한 패키지를 내려받습니다. 처음 설치하거나 `requirements.txt`가 바뀌면 몇 분 정도 걸릴 수 있습니다.
5. 브라우저가 열리면 준비가 끝납니다. 자동으로 열리지 않으면 주소창에 `http://127.0.0.1:8501`을 입력합니다. 회의가 끝날 때까지 실행된 명령 프롬프트 창을 열어 두세요.

## 연결 키 설정하기

API 키는 앱이 Gemini에 요청을 보낼 때 사용하는 비밀값입니다. Google AI Studio에서 키를 발급한 뒤 앱의 **Gemini API 키** 입력칸에 붙여넣으세요. 음성 인식과 회의록 요약에 같은 키를 사용합니다. [Google AI Studio 키 발급 안내](https://aistudio.google.com/docs/api-key)

같은 노트북에서 반복 사용하려면 아래 방법으로 키를 파일에 둘 수 있습니다.

1. `.env.example`을 복사해 파일 이름을 정확히 `.env`로 지정합니다. 탐색기에서 **보기 → 표시 → 파일 확장명**을 켜면 뒤에 `.txt`가 붙었는지 확인할 수 있습니다.
2. 텍스트 편집기로 `.env`를 열고 `GEMINI_API_KEY=` 뒤에 발급받은 키를 붙여넣은 뒤 저장합니다. `GEMINI_API_KEY` 대신 `GOOGLE_API_KEY`도 사용할 수 있습니다.
3. `.env`를 바꾼 뒤에는 앱을 다시 실행합니다. 키가 들어 있는 `.env`는 공유 폴더나 메신저에 올리지 마세요.

### Gemini 모델과 사용 한도

- 음성 인식과 기본 요약은 `gemini-3.5-flash-lite`를 사용합니다. [Gemini 3.5 Flash-Lite 공식 문서](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite)
- 기본 설정에서는 음성 인식과 요약이 같은 Google 프로젝트의 모델 사용 한도를 공유합니다. 발화가 계속되면 1분당 음성 인식 요청 약 30회와 요약 요청 약 2회가 발생할 수 있습니다. 재시도에 따른 요청은 별도로 추가됩니다. 한도에 도달하면 Google AI Studio에서 프로젝트의 한도를 확인하세요. [Gemini 사용 한도 안내](https://aistudio.google.com/docs/rate-limits)

## 회의에서 사용하기

1. 회의 주제와 녹음에서 나올 사내 용어를 적습니다. 예를 들어 주제에 `11월 정산 개선 회의`, 키워드에 `정산 배치, 매출 대사, 김민수`를 입력합니다. 앱은 이 정보를 음성 인식기에 문맥 힌트로 전달합니다.
2. **회의 시작**을 누릅니다. 왼쪽에 경과 시간과 자막이 나타납니다. 말한 뒤 첫 자막은 오디오 약 2초가 쌓이고 음성 인식 서비스가 응답하면 표시됩니다. 화면에는 최근 100개 자막을 표시합니다. 자막은 말뜻을 유지하면서 띄어쓰기, 맞춤법, 문장부호와 명백한 오인식을 가볍게 보정합니다. 숫자나 일부 부정 표현이 달라지면 최초 인식문을 사용합니다.
3. 오른쪽 회의록에는 약 30초마다 새로 인식된 발언이 반영됩니다. 요약 요청이 진행되는 동안에도 녹음과 자막 처리가 계속됩니다.
4. **회의 종료**를 누르고 저장 완료가 표시될 때까지 기다립니다. 마지막 2초 미만의 음성 조각과 대기 중인 변환을 처리한 뒤 필요하면 회의록을 한 번 더 갱신합니다.
5. 화면의 다운로드 버튼을 누르거나 프로젝트의 `output` 폴더에서 파일을 열 수 있습니다. 날짜와 시각은 노트북의 회의 시작 시각입니다. 같은 분에 시작한 회의가 있으면 뒤에 `_2`처럼 번호를 붙입니다.
   - `output/YYYYMMDD_HHMM_회의록.md`는 제목과 목록을 담는 마크다운 문서입니다.
   - `output/YYYYMMDD_HHMM_전체녹취.txt`는 시간 표시가 붙은 전체 보정 자막입니다.

Windows에서는 브라우저 탭을 닫아도 명령 프롬프트가 실행 중이면 녹음이 계속됩니다. 같은 주소를 다시 열고 **회의 종료**를 누르세요. 저장 완료 후 명령 프롬프트에서 `Ctrl+C`를 눌러 앱을 끌 수 있습니다.

### 지난 회의 보기

1. 앱에서 **회의 기록**을 선택합니다.
2. 회의 주제나 날짜로 찾아 원하는 회차를 선택합니다. 같은 주제로 저장된 회의는 시작 순서대로 회차를 표시합니다.
3. 회의록과 시간 표시가 붙은 전체 녹취를 읽거나 다운로드합니다. 기존에 `output` 폴더에 저장된 회의도 목록에 표시됩니다.

### 화면 모드와 회의 기록 복구

- 왼쪽 메뉴의 **밝게 / 어둡게**로 화면 모드를 고를 수 있습니다. 회의록에는 안건, 확정·검토 사항, 담당자·기한이 포함된 할 일 목록이 표시됩니다. Markdown 파일에도 같은 구조로 저장합니다.
- 회의 중 인식이 끝난 자막과 요약을 사용자 전용 SQLite 파일에 순차 저장합니다. 앱이 중단되면 다시 열거나 Ubuntu 창에서 **회의 화면 다시 시작**을 누른 뒤 **이전 회의 복구**를 선택하세요. 저장된 내용은 인터넷과 API 키 없이 Markdown과 텍스트로 내보낼 수 있습니다.
- 인터넷이 끊기거나 서비스가 응답하지 않으면 처리하지 못한 구간이 표시됩니다. 인식 전 오디오는 저장하지 않으므로 중단 시점에 아직 인식되지 않은 발언은 복구할 수 없습니다.

보안 점검 범위와 남은 제약은 [보안 및 복구 설계](SECURITY.md)를 참고하세요.

## 문제가 생겼을 때

| 증상 | 확인할 사항 |
| --- | --- |
| `Python 3.12 or 3.11 is required` | 명령 프롬프트에서 `py -3.12 --version`, `py -3.11 --version`, `python --version` 중 하나가 지원 버전을 보여 주는지 확인합니다. Python 설치 후 새 명령 프롬프트를 열거나 `run.bat`를 다시 실행합니다. |
| 프로젝트 전용 Python 환경을 열 수 없음 | 프로젝트 폴더를 옮겼거나 Python을 다시 설치했다면 앱을 끈 후 `.venv`를 `.venv-old`로 이름을 바꾸고 `run.bat`를 다시 엽니다. 새 환경이 만들어집니다. |
| 패키지 설치 실패 | 인터넷 연결과 패키지 다운로드가 가능한 네트워크인지 확인한 뒤 `run.bat`를 다시 실행합니다. |
| 화면을 열 수 없음 또는 8501 포트 사용 중 | 실행 창에 표시된 오류를 읽고, 이미 열린 회의록 앱이 있는지 확인합니다. 회의 중인 앱은 먼저 저장한 후 종료하세요. |
| 자막이 나오지 않음 | Windows에서 내장 마이크가 기본 입력인지, 음소거됐는지, 입력 막대가 움직이는지 확인합니다. 권한이나 기본 마이크를 바꿨다면 새로 회의를 시작합니다. |
| 멀리 있는 사람의 말이 자주 빠짐 | 노트북을 참석자 사이에 두고 Windows 입력 볼륨을 점검합니다. 최대 3배 자동 증폭을 적용해도 작은 목소리가 주변 소음에 묻히면 감지하기 어렵습니다. |
| 서비스 오류가 표시됨 | 연결, 키, 사용 한도, 모델 접근 권한을 각각 확인합니다. 변환에 실패한 음성 구간은 누락될 수 있으므로 저장 전 화면의 오류를 확인합니다. |
| `output` 폴더에 저장할 수 없음 | 폴더 쓰기 권한과 남은 디스크 공간을 확인한 후 **파일 다시 저장**을 누릅니다. 화면에서 결과를 직접 다운로드할 수도 있습니다. |

## 프로젝트 구성

| 파일 | 역할 |
| --- | --- |
| `app.py` | Streamlit으로 구성한 브라우저 화면과 회의 제어 |
| `meeting_session.py` | 녹음, 변환, 요약 작업의 연결 및 회의 종료 후 파일 저장 |
| `meeting_storage.py` | 중단된 회의 복구와 결과 파일 저장 |
| `meeting_history.py` | 저장 파일에서 지난 회의와 회차 조회 |
| `audio_processor.py` | 기본 마이크 입력, 음량 보정, Gemini 음성 인식 |
| `llm_summarizer.py` | Google GenAI로 새 발언을 기존 회의록에 반영 |
| `requirements.txt` | 설치에 필요한 Python 패키지 목록 |
| `.env.example` | 키를 파일로 설정할 때 사용하는 예제 |
| `run.bat` | Windows 패키지 설치 및 앱 실행 |

마이크 녹음, 음성 인식, 회의록 요약은 별도로 진행됩니다. 녹음은 16 kHz 단일 채널 16비트 오디오로 처리하며, 장치가 16 kHz 입력을 지원하지 않으면 지원되는 기본 입력 속도로 녹음해 변환합니다. 매 2초마다 이전 구간의 마지막 0.8초를 앞에 붙여 경계에 걸친 단어 인식을 돕습니다. 평균 진폭이 낮아 무음으로 판단한 구간은 음성 인식 요청에서 제외합니다.
